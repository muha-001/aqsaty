# تحسين العقود والأقساط والبحث المتقدم

> **الهدف:** توسيع دورة حياة العقد وإضافة أدوات مالية وبحثية قابلة للتدقيق دون كسر البيانات الحالية.

## المعمارية

تُحفظ التغييرات التاريخية داخل العقد كسجل append-only، وتبقى الدفعات كسجلات مستقلة تسمح بعدة دفعات في اليوم نفسه. تُحتسب الغرامات والرصيد من طبقة المجال، بينما تبقى التصفية والفرز دوالًا نقية قابلة للاختبار وتستخدمها لوحة الإدارة.

## خطة التنفيذ

- [x] فحص نماذج العقود الحالية ومكونات الواجهة.
- [ ] إضافة أنواع تاريخ العقد، الغرامات، ورسوم التمديد، مع ترقية قراءة البيانات القديمة بقيم افتراضية.
- [ ] إضافة اختبارات فشل ثم تنفيذ: الدفعات الجزئية والمتعددة، الغرامة التلقائية، التمديد، الإلغاء بسبب، وإعادة الجدولة الكاملة.
- [ ] ربط عمليات العقد الجديدة بنماذج الإدارة وسجل النشاط.
- [ ] إضافة دوال بحث وتصفية وفرز نقية حسب العميل والهاتف والعقد والمنتج والتسلسل والحالة والتاريخ والمتبقي.
- [ ] إضافة عناصر التحكم في لوحة الإدارة وتحسين جدول النتائج للهاتف.
- [ ] تشغيل lint وtypecheck والاختبارات والبناء وaudit ثم الرفع إلى main.

## قواعد مالية افتراضية

- الغرامة تُحسب كنسبة يومية قابلة للتعديل من المبلغ المتبقي للقسط المتأخر، مع حد أقصى يمنع التضخم غير المقصود.
- الدفعة الجزئية لا تتجاوز المتبقي للقسط وتُسجل كسجل مستقل حتى لو تكرر التاريخ.
- الإلغاء يتطلب سببًا ويغيّر الحالة دون حذف العقد أو دفعاته.
- إعادة الجدولة الكاملة تعيد توزيع الرصيد غير المدفوع على عدد وتواريخ جديدة مع الحفاظ على الدفعات السابقة.
