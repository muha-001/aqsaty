# aqsaty

نظام عربي RTL لإدارة الأقساط محليًا، مبني بواجهة **React + TypeScript + Vite** ومجهز للنشر على GitHub Pages.

## المبدأ التشغيلي

يعمل المشروع محليًا أولًا؛ تحفظ بيانات الزبائن والعقود والدفعات داخل **IndexedDB** في متصفح جهاز الإدارة، مع ترحيل تلقائي للبيانات القديمة من `localStorage` عند التحديث. توجد مزامنة سحابية اختيارية عبر Supabase عند تفعيل المصادقة والإعدادات، مع فحص `revision` قبل الكتابة لمنع استبدال تحديث جهاز آخر بصمت. يمكن تصدير نسخة احتياطية مشفّرة بصيغة JSON وحفظها يدويًا على USB أو جهاز موثوق.

> التخزين دائم داخل جهاز الإدارة وليس بين عدة أجهزة. حذف بيانات المتصفح أو فقدان الجهاز قد يؤدي إلى فقدان البيانات؛ لذلك يجب أخذ نسخة احتياطية مشفّرة دوريًا.

## تشغيل المشروع

```bash
npm install
npm run dev
```

## فحص وبناء نسخة الإنتاج

```bash
npm run check
npm test
npm run lint
npm run build
```

تُنتج نسخة الإنتاج داخل مجلد `dist`.

يشغّل GitHub Actions تلقائيًا lint وTypeScript والاختبارات والبناء وفحص الاعتماديات على Pull Request وعلى فرع `main` قبل النشر.

## النشر على GitHub Pages

يحتوي المشروع على Workflow داخل `.github/workflows/deploy-pages.yml` يبني المشروع وينشر مجلد `dist` تلقائيًا عند كل Push إلى فرع `main`.

من إعدادات المستودع، اختر:

```text
Settings → Pages → Source: GitHub Actions
```

## الوظائف الحالية

- إدارة الزبائن والعقود المتعددة لكل زبون.
- إنشاء جدول 6 أو 10 أو 12 شهرًا مع معالجة فرق التقريب في القسط الأخير.
- تسجيل دفعات نقدية أو تحويل أو بطاقة.
- حساب المسدد والمتبقي والمتأخرات.
- كشف العميل عبر رقم الهاتف.
- تذكير القسط عبر WhatsApp برسالة جاهزة وبإرسال يدوي.
- إدارة المنتجات والمخزون والأرقام التسلسلية والصور.
- تخزين دائم محلي داخل IndexedDB مع ترحيل تلقائي من localStorage.
- تغيير كلمة مرور الإدارة من لوحة النسخ والإعدادات.
- حفظ كلمة المرور كقيمة مجزأة باستخدام PBKDF2 بدل تخزينها كنص واضح.
- تصدير واستيراد النسخ الاحتياطية المشفّرة.
- واجهة عربية متجاوبة مع الهاتف.
- حركة واجهة خفيفة مع دعم `prefers-reduced-motion`.

## تغيير كلمة المرور

بعد الدخول إلى لوحة الإدارة، افتح **النسخ والإعدادات**، ثم أدخل كلمة المرور الجديدة واضغط **حفظ كلمة المرور**. التغيير محلي على نفس المتصفح والجهاز، ولا ينتقل إلى جهاز آخر.

## المزامنة السحابية الاختيارية عبر Supabase

يدعم المشروع الآن مزامنة اختيارية بين الأجهزة عبر Supabase، مع إبقاء IndexedDB كنسخة محلية عند انقطاع الإنترنت. لا تُفعّل المزامنة تلقائيًا إلا بعد إعداد مشروع Supabase ومصادقة المستخدم.

1. أنشئ مشروعًا مجانيًا في [Supabase](https://supabase.com/).
2. افتح SQL Editor وشغّل الملف `supabase/schema.sql`.
3. أنشئ حسابًا في Supabase، ثم أنشئ Workspace وأضف `auth.users.id` إلى `aqsaty_workspace_members` بدور `owner`.
4. انسخ `.env.example` إلى `.env.local` وأدخل `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` و`VITE_SUPABASE_WORKSPACE_ID`.
5. استخدم مفتاح `anon` العام فقط في الواجهة؛ ممنوع وضع `service_role` داخل `.env.local` الخاص بالواجهة أو داخل المستودع.

المزامنة الحالية تحفظ نسخة قاعدة البيانات المحلية كاملة داخل سجل سحابي واحد لكل Workspace. بعد فتح **لوحة الإدارة → النسخ والإعدادات**، يمكن تسجيل الدخول بحساب Supabase عبر البريد وكلمة المرور أو باستخدام GitHub؛ عند نجاح الدخول تُسحب النسخة السحابية وتُرفع التغييرات اللاحقة تلقائيًا. قبل الكتابة، يتم فحص `revision` لمنع overwrite الصامت عند تعديل جهازين في الوقت نفسه؛ عند التعارض يجب سحب آخر نسخة ومراجعة التعديلات. تسجيل الخروج لا يحذف البيانات المحلية. يوصى بالاحتفاظ بنسخ احتياطية مستقلة من Supabase.

لتفعيل GitHub، افتح **Authentication → Sign In / Providers → GitHub** داخل مشروع Supabase، فعّل المزود وأدخل Client ID وClient Secret من GitHub OAuth App. أضف رابط callback الظاهر في Supabase، وأضف `https://muha-001.github.io/aqsaty/` إلى Redirect URLs. بعد ذلك يظهر زر **تسجيل الدخول باستخدام GitHub** داخل بطاقة المزامنة.

## ملاحظة الخصوصية

لا ترفع ملفات النسخ الاحتياطية إلى GitHub لأنها قد تحتوي على أرقام هواتف وبيانات مالية. كلمة مرور الإدارة محلية داخل الجهاز وليست نظام مصادقة لخادم. إذا كان المطلوب تشغيل النظام من عدة أجهزة أو منح صلاحيات متعددة للموظفين، فستحتاج النسخة المستقبلية إلى خادم وقاعدة بيانات — وهو خارج نطاق التخزين المحلي الحالي.
